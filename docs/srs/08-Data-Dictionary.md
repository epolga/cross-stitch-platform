# Data Dictionary — cross-stitch-platform

**Status:** Draft, consolidated from `01-LLD-Website.md` §2, `02-LLD-Photo-to-Cross-Stitch-Converter.md`
§2, `03-LLD-Pinterest-Automation.md` §2, `04-LLD-Uploader.md` §2, and `06-API-Specification.md`
**Date:** 2026-07-11

**Purpose:** Single canonical reference for every DynamoDB table/entity in the platform —
this document exists specifically because `docs/integration/dynamodb-schema.md` (the
pre-existing formal schema doc) has not kept pace with feature development (`05-SAD.md`
§5.2, item 4). This file aggregates what the LLD documents already established per
component; it does not introduce new research. See the referenced LLD for the
component-specific context each table is used in, and `07-ERD.md` for how these tables
relate to each other.

**Reading this table:** "Consumers" lists every component known to read and/or write each
table (W = write, R = read). A table with only one consumer still gets its own entry here
for completeness and because it may gain a second consumer later.

## 1. `CrossStitchItems`

**Key:** PK `ID` (S), SK `NPage` (S). **GSIs:** `Designs-index` (PK `EntityType` / SK
`NGlobalPage`), `DesignsByID-index` (PK `EntityType` / SK `DesignID`), `ID-DesignID-index`
(PK `ID` / SK `DesignID`).
**Consumers:** Website (R), Uploader (W — sole creator of new `DESIGN` rows), autopinner (R
unpinned designs, W pin status), pinterest-agent (R, for `DESIGN_PIN_MAP`/
`DESIGN_PERFORMANCE` construction only).

## 11. `CrossStitchBusinessHistory`

**Key:** PK `EntityType` (S), SK `SortKey` (S) — single-table design, twelve logical entity
types.
**Consumers:** pinterest-agent only (sole reader and writer of every entity type in this
table).

| EntityType | SortKey pattern | Key attributes |
|---|---|---|
| `DAILY_BUSINESS` | `date` | `spend`, `impressions`, `clicks`, `ctr`, `cpc`, `outboundClicks`, `ga4Sessions`, `ga4PaidSessions`, `ga4OrganicSessions`, `ga4ReferralSessions`, `ga4TotalAllSessions`, `adsenseRevenue`, `revenuePerHundredSessions`, `profit`, `usdIlsRate` |
| `AI_ANALYSIS` | `generatedAt#type` | `analysisType`, `forDate`, `reasoning`, `markdownS3Key`, trend-only: `recommendedAction`, `sourceHistoryRange`, `totalDaysAnalyzed`; design-only: `topAlbums`, `underperformingAlbums`, `designDirectionsToCreate` |
| `DESIGN_PIN_MAP` | `designId` (5-digit padded) | pin linkage — **cross-table reference to `CrossStitchItems`**, see `07-ERD.md` §4 |
| `DESIGN_PERFORMANCE` | `snapshotDate#designId` | rolling 30-day impressions/clicks/saves, `savesPerDay`, `impressionsPerDay` — also cross-table |
| `ANOMALY_EVENT` | `detectedAt#metric` | `metric`, observed value, trailing mean, standard deviation, `notified: bool` |
| `PROMOTED_AD_STATS` | `date#adId` | spend, impressions, clicks, CTR |
| `LANDING_PAGE_STATS` | `date#page` | Pinterest session counts |
| `PIN_ATTRIBUTION` | `date#adId` | estimated per-pin revenue/profit |
| `PINTEREST_TOKEN` | `"CURRENT"` (singleton) | `access_token`, `refresh_token`, `expires_at_utc`, `scope`, `writtenAt`, `refreshedAt` |
| `BLOCKED_IP` | `ip` | `reason`, `blockedAt`, `ttl` (native DDB TTL, default +30d) |
| `WATCHED_IP` | `ip` | `reason`, `watchedAt`, `ttl` (native DDB TTL, default +3d) |
| `IP_HISTORY` | `ip#at` | `action` (`"blocked"`\|`"watched"`), `reason`, `at` — **no TTL, never expires** |

## 12. Cross-cutting known issues (see `05-SAD.md` §5.2 for full discussion)

1. Six historical spellings of the design-level Pinterest pin-ID attribute (§1.1).
2. Two parallel, unreconciled user representations: `CrossStitchUsers` (§2) and the legacy
   `CrossStitchItems` `EntityType="USER"` rows (§1.3).
3. No schema-version attribute on any table — every writer hard-codes its own column list.
4. Tables in §5–§10 (all newer Website/Converter features) are not named in the formal
   `docs/integration/dynamodb-schema.md` and their exact table names/key schemas were not
   independently re-verified for this dictionary beyond what the LLD and API-spec research
   already established — confirm against the live DynamoDB console before treating any
   detail in §5–§10 as authoritative for anything beyond the conceptual attribute list.
5. `CrossStitchBusinessHistory` (§11) is the one table with no known drift or duplication
   issue — it has exactly one writer (pinterest-agent) and a consistent `EntityType`/
   `SortKey` convention across all twelve entity types.
