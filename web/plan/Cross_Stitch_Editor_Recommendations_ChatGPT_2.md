# Рекомендации по развитию cross-stitch.com Editor

_Рабочий roadmap, июль 2026_

## Главная цель

Не пытаться сделать «ещё один универсальный cross-stitch editor».

Основная конкурентная позиция должна быть уже и сильнее:

> **Лучший путь от фотографии к чистой, красивой и реально вышиваемой cross-stitch схеме.**

То есть выигрывать прежде всего в задаче:

**Photo → Stitchable Pattern**

а не в количестве профессиональных функций редактора.

---

# 1. Сначала доказать качество генератора

Это важнее добавления очередной функции.

Нужно проверить, действительно ли алгоритм cross-stitch.com создаёт более удачные схемы, чем основные конкуренты.

## Сделать benchmark

Подготовить 30–50 разных изображений:

- кошка;
- собака;
- человеческий портрет;
- пейзаж;
- цветы;
- предмет на простом фоне;
- предмет на сложном фоне;
- рисунок;
- watercolor;
- изображение с градиентами;
- тёмная фотография;
- светлая фотография;
- изображение с мелкими деталями;
- изображение с большими однородными областями.

Одни и те же картинки прогнать через несколько сервисов:

- cross-stitch.com;
- FlossCross;
- Knytstudio;
- Pic2Pat;
- ещё один сильный image-to-pattern converter.

Параметры нужно сделать максимально сопоставимыми:

- похожий размер схемы;
- похожее количество цветов;
- одинаковая или сопоставимая палитра ниток.

## Что сравнивать

| Критерий | Вопрос |
|---|---|
| Похожесть | Насколько хорошо узнаётся исходное изображение? |
| Stitchability | Насколько такую схему удобно реально вышивать? |
| Confetti | Есть ли одиночные или бессмысленные мелкие островки? |
| Palette | Есть ли лишние очень похожие цвета? |
| Detail | Не потеряны ли важные детали? |
| Thread changes | Не требует ли схема слишком частой смены ниток? |
| Manual work | Сколько ручной правки требуется после генерации? |
| Overall result | Какую схему пользователь выбрал бы для вышивания? |

## Очень желательно сделать blind comparison

Показывать нескольким вышивальщицам результаты без названий сервисов.

Например:

**Pattern A / Pattern B / Pattern C**

и спрашивать:

> Какую из этих схем вы предпочли бы реально вышивать?

Это даст намного более полезную информацию, чем сравнение списка функций.

---

# 2. Проверить главное предполагаемое преимущество: отсутствие confetti

У cross-stitch.com нет функции «удалить confetti», потому что алгоритм должен создавать дизайн **без confetti изначально**.

Это потенциально значительно сильнее cleanup-функции.

Но это преимущество нужно проверить на большом количестве изображений.

Важно доказать не только:

> меньше confetti

но:

> **меньше confetti без заметной потери качества изображения.**

То есть преимущество существует только если выполняются одновременно оба условия:

**cleaner pattern + сохранение важных деталей**

Если benchmark это подтверждает, это должно стать одной из центральных особенностей продукта.

Возможное позиционирование:

> **Clean cross-stitch patterns from the start. No confetti cleanup required.**

Абсолютные рекламные формулировки использовать только после достаточного тестирования.

---

# 3. Не строить конкуренцию вокруг количества функций редактора

Не нужно пытаться догнать FlossCross, Stitch Fiddle или Needlepix по принципу:

- у них fractional stitches → добавить fractional stitches;
- у них layers → добавить layers;
- у них French knots → добавить French knots;
- у них десять floss palettes → добавить десять palettes.

Так можно потратить много месяцев и получить просто ещё один хороший editor.

Основной вопрос должен оставаться:

> **Почему человек должен загрузить фотографию именно в cross-stitch.com?**

Ответ должен быть связан прежде всего с качеством готовой схемы.

---

# 4. Сделать существующие simulated stitches частью основного workflow

Simulated stitches уже есть.

Поэтому ничего нового здесь строить не требуется.

Нужно проверить, достаточно ли хорошо пользователь видит эту функцию.

Желательный workflow:

```text
Upload photo
    ↓
Generate
    ↓
Original | Pattern | Simulated stitches
    ↓
Edit
```

Simulated stitches должны помогать пользователю сразу понять:

> «Вот примерно как моя фотография будет выглядеть вышитой».

Это не просто display mode редактора.

Это часть первого впечатления от результата генерации.

---

# 5. Следующая большая функция — Save / Reopen Project

После проверки качества генератора я бы поставил это первым большим product feature.

Важно: речь не о PDF.

Пользователь должен иметь возможность сохранить **редактируемый проект**.

Пример:

```text
My Patterns

Black Cat
Jerusalem
Flowers
Portrait
```

Для каждого:

- Open;
- Edit;
- Duplicate;
- Rename;
- Delete.

## Что сохранять

Минимально:

- user ID;
- pattern/project ID;
- название;
- grid;
- размеры;
- palette;
- цвета;
- состояние схемы после ручного редактирования;
- настройки, необходимые редактору;
- created date;
- updated date.

Позже можно добавить:

- исходное изображение;
- preview;
- stitching progress;
- version history.

## Зачем это нужно

Сейчас потенциальный workflow:

```text
Generate → Edit → PDF → пользователь ушёл
```

Нужен workflow:

```text
Generate → Edit → Save
                  ↓
              вернулся
                  ↓
           Continue Editing
```

В идеале один и тот же проект должен открываться после входа в аккаунт на другом устройстве.

# 6. Превратить существующий каталог в редактируемую библиотеку

Это отдельное важное направление, которое хорошо связывает две уже существующие части cross-stitch.com:

- большой каталог готовых дизайнов;
- собственный editor.

Идея:

> **Любой готовый design можно использовать как starting point и при желании переделать под себя.**

На странице существующего дизайна пользователь должен видеть не только:

```text
Download PDF
```

но и, например:

```text
Customize this pattern
```

или:

```text
Make it your own
```

Я бы предпочёл именно **Customize this pattern**, а не `Edit pattern`.

`Edit` звучит как функция профессионального графического редактора и может отпугнуть обычного пользователя.

`Customize` формулирует понятный результат:

> «Мне нравится эта схема, но я хочу немного изменить её под себя».

---

## Почему это может быть востребовано

Готовая схема очень часто подходит человеку не полностью.

Типичные ситуации:

- нравится кот, но нужен другой цвет;
- хочется убрать цветы или фон;
- хочется добавить имя;
- нужен только один элемент существующего дизайна;
- хочется отзеркалить объект;
- хочется расположить два одинаковых элемента рядом;
- схема слишком сложная — пользователь хочет её упростить;
- хочется заменить несколько цветов;
- хочется добавить небольшой собственный элемент.

Сейчас в такой ситуации каталог работает как бинарный выбор:

```text
Pattern подходит → скачать
Pattern не подходит → уйти искать другой
```

После появления Customize:

```text
Pattern подходит почти
        ↓
Customize
        ↓
Editor
        ↓
Изменить то, что не нравится
        ↓
Save / PDF
```

Это увеличивает полезность **каждого существующего дизайна**.

Схема уже не обязана идеально совпадать с желаниями пользователя.

Она может быть хорошей исходной точкой.

---

## Это не уникальная функция сама по себе

Саму идею remix уже используют отдельные конкуренты.

Например, Knytstudio позволяет брать опубликованные patterns и создавать собственную изменяемую копию.

Поэтому конкурентное преимущество cross-stitch.com не должно формулироваться как:

> «У нас можно редактировать существующую схему».

Сильнее выглядит комбинация:

> **Тысячи уже существующих готовых дизайнов, каждый из которых может стать starting point для собственного варианта.**

Это особенно важно, потому что cross-stitch.com уже обладает большим каталогом.

Новому editor/community-продукту сначала нужно годами накапливать библиотеку, пригодную для remix.

У cross-stitch.com исходный материал уже существует.

---

## Как должен выглядеть workflow

На странице дизайна:

```text
BLACK CAT CROSS-STITCH PATTERN

[ Download PDF ]

[ Customize this pattern ]
```

После `Customize this pattern`:

```text
Existing Design
      ↓
Create editable user copy
      ↓
Open Editor
      ↓
User changes pattern
      ↓
Save Project
      ↓
PDF / later OXS
```

Очень важно:

**оригинальный design никогда не изменяется.**

Пользователь всегда работает с собственной копией.

---

## Модель данных

Save Project и Customize Existing Pattern желательно проектировать вместе.

У пользователя должна появиться единая сущность:

```text
UserPattern / Project
```

У проекта может быть разное происхождение:

```text
Project
 ├── createdFromPhoto
 ├── createdFromExistingDesign
 └── createdFromBlank
```

Для remix существующего дизайна полезно сохранить:

```text
projectId
userId
sourceType = existingDesign
sourceDesignId
projectName
grid
palette
dimensions
editorState
createdAt
updatedAt
```

`sourceDesignId` позволяет:

- знать, откуда произошёл пользовательский вариант;
- показывать ссылку на оригинал;
- анализировать, какие дизайны чаще всего customiz'ят;
- позже показывать похожие starting points.

---

## Как это может выглядеть в My Patterns

```text
MY PATTERNS

Modified Black Cat
Based on Black Cat #3517

My Dog
Created from photo

Flowers for Anna
Based on Flowers #2184

New Pattern
Created from scratch
```

То есть Save Project становится общей системой не только для photo converter.

Она объединяет весь editor.

---

## Не требовать регистрацию до начала редактирования

Желательно позволить пользователю нажать:

```text
Customize this pattern
```

и сразу открыть editor.

Не заставлять сначала создавать аккаунт.

Регистрацию/вход логичнее предложить тогда, когда пользователь уже сделал изменения и нажимает:

```text
Save my pattern
```

То есть:

```text
Customize
    ↓
Edit
    ↓
пользователь уже вложил усилия
    ↓
Save
    ↓
Sign in / Create account
```

Так человек сначала видит ценность функции.

---

## Что пользователь должен уметь изменить

Первая версия не обязана превращаться в профессиональный graphics editor.

Достаточно использовать уже имеющиеся возможности редактора и дать человеку:

- менять цвета;
- удалять stitches;
- добавлять stitches;
- использовать undo;
- скрывать цвета;
- работать с существующей palette;
- видеть simulated stitches;
- снова генерировать PDF.

Следующими особенно полезными операциями могут быть:

- выделение области;
- move/copy;
- mirror;
- duplicate;
- crop;
- replace color;
- массовая замена одного DMC другим.

Для сценария Customize эти операции могут быть полезнее, чем редкие специальные типы stitches.

---

## Сильные сценарии использования

### 1. Замена цвета

```text
White cat
   ↓
Customize
   ↓
Replace white shades
   ↓
Ginger cat
```

### 2. Удаление элемента

```text
Cat + flowers
     ↓
Customize
     ↓
Remove flowers
     ↓
Cat only
```

### 3. Добавление персонализации

```text
Existing design
      ↓
Customize
      ↓
Add name / initials / date
```

### 4. Использование части схемы

```text
Large design
    ↓
Select fragment
    ↓
Create smaller personal pattern
```

### 5. Mirror / duplicate

```text
One bird
   ↓
Duplicate + mirror
   ↓
Two birds facing each other
```

Это очень естественные пользовательские задачи и хороший аргумент в пользу развития операций над выделенной областью.

---

## Пользовательское сообщение на страницах каталога

Хорошая формулировка рядом с PDF:

> **Not quite what you need? Customize this pattern.**

Она обращается ровно к пользователю, которому схема **почти** подходит.

Другой вариант:

> **Like this design? Make it your own.**

Можно тестировать оба варианта.

---

## Почему эта функция стратегически важна

Она создаёт второй крупный вход в editor.

Сегодня основной editor flow:

```text
MY IMAGE
   ↓
Generate
   ↓
Edit
```

После Customize появляется:

```text
                    EDITOR
                   /      \
                  /        \
          My photo          Existing design
             ↓                    ↓
          Generate             Customize
                  \            /
                   \          /
                       Edit
                        ↓
                       Save
                        ↓
                    PDF / OXS
```

Таким образом editor перестаёт быть только photo converter.

Он становится общей рабочей средой для персональных patterns.

---

## Каталог превращается из контента в product infrastructure

Это важное изменение.

Сейчас каталог в основном выполняет функции:

- SEO;
- Pinterest acquisition;
- готовые бесплатные PDFs.

После Customize он становится ещё и:

> **огромной библиотекой templates для editor.**

То есть существующие тысячи designs получают дополнительную ценность без необходимости создавать тысячи новых editor features.

Это одно из немногих преимуществ, которое трудно быстро повторить новому standalone converter.

---

## Что измерять после запуска Customize

Добавить события:

```text
CustomizeClicked
CustomizeEditorOpened
CustomizedPatternEdited
CustomizedPatternSaved
CustomizedPatternPdfDownloaded
CustomizedPatternReturned
```

Отдельно измерять:

```text
sourceDesignId
```

Это позволит увидеть:

- какой процент посетителей design pages нажимает Customize;
- какие категории чаще customiz'ят;
- какие дизайны являются хорошими starting points;
- сколько пользователей после Customize сохраняют проект;
- сколько потом возвращаются;
- создаёт ли эта функция дополнительную регистрацию;
- уменьшает ли она уход пользователей с design pages.

Особенно интересна метрика:

> **Customize → meaningful edit**

То есть не просто открыли editor, а действительно изменили pattern.

---

## Возможное дальнейшее развитие

Если функция окажется востребована, позже можно добавить:

### Suggested customizations

Например:

- Change colors
- Remove background
- Mirror
- Add text
- Make smaller

### Variants

Показывать:

> Create another version

без изменения уже сохранённого варианта.

### User remix gallery

Это уже значительно более поздняя стадия.

Не следует сразу превращать продукт в social network.

Сначала нужно доказать, что пользователи вообще хотят переделывать готовые designs.

# 7. Проверить PDF как реальный рабочий инструмент


PDF нужно оценивать не только визуально.

Нужно проверить:

- удобно ли читать symbols;
- хорошо ли видны линии сетки;
- удобна ли разбивка на страницы;
- не перекрываются ли страницы;
- понятна ли легенда;
- указан ли DMC;
- удобно ли находить продолжение схемы на соседней странице;
- нормально ли схема печатается в B/W;
- пригоден ли PDF для популярных stitching-приложений.

Особенно имеет смысл проверить **Pattern Keeper** и аналогичные приложения.

Если PDF плохо импортируется или распознаётся, это стоит исправить раньше многих декоративных функций.

# 8. После этого — OXS import/export

OXS полезен по двум причинам.

## Export

Пользователь может продолжить работу с pattern в другом совместимом приложении.

Это уменьшает ощущение закрытой системы.

## Import

cross-stitch.com становится не только photo converter, но и местом, где можно открыть существующий pattern и работать с ним.

Однако OXS всё же ниже по приоритету, чем:

- качество генерации;
- Save Project;
- хороший PDF.

---

# 9. Затем — Stitch Mode

После появления сохранённых проектов имеет смысл добавить режим реальной вышивки.

Workflow:

```text
Saved Pattern
     ↓
Start Stitching
     ↓
select DMC color
     ↓
mark completed stitches
     ↓
progress automatically saved
```

Возможности первой версии:

- выбрать один цвет;
- подсветить его stitches;
- скрывать другие цвета;
- помечать stitch как выполненный;
- отменять отметку;
- показывать процент выполнения;
- сохранять progress.

Например:

```text
DMC 310

Completed:
428 / 1,834 stitches

23.3%
```

Это меняет модель использования продукта.

Без Stitch Mode пользователь нужен сайту несколько минут или часов.

Со Stitch Mode он может возвращаться к одной схеме неделями.

---

# 10. Backstitch — после основных частей workflow

Backstitch действительно полезен.

Особенно:

- для контуров;
- лиц;
- животных;
- надписей;
- мелких деталей;
- улучшения автоматически созданного дизайна.

Поэтому backstitch имеет смысл добавить раньше многих других специальных типов stitches.

Но не раньше:

1. проверки качества генерации;
2. Save Project;
3. нормального export workflow.

---

# 11. Fractional stitches, petite, French knots и другие advanced features — позже

Их не нужно исключать навсегда.

Но сейчас это не основной способ выиграть конкуренцию.

Добавлять их следует:

- по реальным запросам пользователей;
- когда базовый workflow уже работает;
- когда понятно, что editor начинают использовать не только для фото-конверсии, но и для профессионального дизайна.

---

# 12. Text → Pattern пока не приоритет

Функция выглядит современно, но не создаёт сильного moat.

Пользователь уже может сделать:

```text
Text
 ↓
ChatGPT / Gemini / image generator
 ↓
Image
 ↓
cross-stitch.com
```

Поэтому значительно важнее хорошо решить специализированную задачу:

> **Image → good stitchable pattern**

чем повторять общий AI image generation внутри собственного продукта.

---

# 13. Построить полный пользовательский путь

Целевая структура продукта:

```text
DISCOVER
Google / Pinterest / ready-made patterns
        ↓
CREATE
Upload own image
        ↓
GENERATE
Clean stitchable pattern
        ↓
PREVIEW
Simulated stitches
        ↓
EDIT
Manual corrections
        ↓
SAVE
Editable project
        ↓
EXPORT
PDF / OXS
        ↓
STITCH
Progress tracking
        ↓
RETURN
Continue tomorrow
```

Задача — не просто увеличить количество возможностей editor.

Задача — сделать так, чтобы пользователю не требовался другой сервис ни на одном основном этапе этого пути.

# 14. Использовать существующий каталог как acquisition funnel

У cross-stitch.com уже есть то, чего нет у многих standalone converters:

**большой каталог готовых designs.**

Поэтому существуют два разных входа.

### Прямой вход

```text
Google:
photo to cross stitch
```

# 17. Измерять не только Opened / Generated / PDF

Текущая воронка полезна:

```text
Opened
   ↓
Generated
   ↓
PDF
```

Но она измеряет главным образом один визит.

Для оценки продукта нужна более длинная воронка:

```text
Editor Opened
      ↓
Image Uploaded
      ↓
Pattern Generated
      ↓
Pattern Edited
      ↓
Simulated View Used
      ↓
Project Saved
      ↓
PDF Downloaded
      ↓
Returned within 7 days
      ↓
Returned within 30 days
```

Ещё один важный event:

> **Generated Second Pattern**

Человек, который вернулся и создал второй design, намного важнее человека, который случайно один раз скачал PDF.

# 18. Отдельно измерять качество результата

Analytics не покажет, почему пользователь ушёл.

Нужно иногда напрямую спрашивать после генерации.

Очень простой feedback:

> **Are you happy with this pattern?**

- Yes
- Mostly
- No

При `No`:

> What is the main problem?

- Doesn't look enough like the image
- Too many colors
- Too much detail
- Lost important details
- Hard to stitch
- Other

Это позволит улучшать именно generator, а не угадывать причины поведения по GA4.

# 19. Что пока НЕ делать

Пока не стоит тратить основное время на:

- десятки дополнительных floss brands;
- сложные layers;
- collaboration;
- social/community system;
- AI text generation;
- профессиональную typography;
- сложную version history;
- десятки специальных stitch types;
- копирование всех функций FlossCross.

Это может понадобиться позже.

Но сейчас каждую новую функцию нужно проверять вопросом:

> **Поможет ли она сделать Photo → Pattern заметно лучше или удержит пользователя внутри основного workflow?**

Если нет — скорее всего, она может подождать.

# Главный принцип

Не пытаться победить конкурентов формулой:

> **«У нас больше функций».**

Пытаться победить формулой:

> **«Здесь можно либо превратить свою фотографию в хорошую вышиваемую схему, либо взять одну из тысяч готовых схем и переделать её под себя — а затем сохранить, довести до ума и вышить».**

Таким образом, стратегическая модель становится шире:

**Generate better → Customize existing designs → Save → Export → Stitch → Return**

Сильная сторона cross-stitch.com должна быть не только в editor как таковом, а в комбинации:

- собственного Photo → Pattern алгоритма;
- большого готового каталога;
- возможности превратить любой подходящий design в личный editable variant;
- сохранения пользовательских проектов;
- полного дальнейшего stitching workflow.

Это и должно определять roadmap.
